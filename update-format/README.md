# Формат обновления прайсов PRO OPTIMA

Этот формат нужен для сценария:

1. Вы присылаете в ChatGPT новый прайс существующего или нового поставщика.
2. ChatGPT сопоставляет позиции с текущим `supplierCatalog`, сохраняет стабильные ID там, где товар тот же, определяет новые/исчезнувшие позиции и связи с нашими товарами.
3. ChatGPT отдаёт `PRO_OPTIMA_UPDATE_....json`.
4. В Admin: **Настройки → Обновление прайсов / предложений → Применить UPDATE**.
5. Railway делает резервную копию и применяет только перечисленные изменения.

UPDATE **не заменяет**:
- историю заявок;
- остатки;
- перемещения;
- старые исполненные заявки.

## Поля

`suppliersUpsert`
: новый поставщик или изменение карточки существующего.

`catalogUpsert`
: позиции каталога поставщика. Для совпавшего товара желательно сохранять старый `id`, чтобы связи не рвались.

`catalogRetireIds`
: позиции, которых больше нет в новом прайсе. Они не удаляются, а получают `availability = unavailable`.

`catalogLinks`
: связь позиции каталога с нашим товаром (`usedProductId` + `product.catalogLinks`).

`productPatches`
: точечные изменения наших товаров: catalogLinks, выбранный заказник, branch-настройки, аналоги наших товаров.

`offersUpsert`
: рабочие строки цены/единицы, участвующие в сравнении и формировании заявок.

## Правило для новых прайсов

Непривязанные позиции остаются только в `supplierCatalog` и показываются в Admin → **Предложения**.
Они не становятся «нашими товарами» автоматически.
